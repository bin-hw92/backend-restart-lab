# 지출 예제 연습문제

성적 예제의 첫 수정·결과 확인을 마쳤으므로 이제 지출 예제로 넘어갑니다. 추가 성적 문제는 필요할 때 다시 풀 수 있습니다.

수정할 파일은 [ExpenseSummaryJava8.java](ExpenseSummaryJava8.java)와 [ExpenseSummaryJava21.java](ExpenseSummaryJava21.java)입니다. 같은 입력·같은 기능을 두 파일에 각각 작성하세요. 원래 `ExpenseSummary.java`는 보관용입니다.

## 먼저 현재 결과 확인

```sh
cd ~/Desktop/project/backend-restart-lab/java-basics
bash run-sample.sh 8 expense
bash run-sample.sh 21 expense
```

현재 입력은 FOOD 12000원, BOOK 25000원, FOOD 9000원입니다. 전체 46000원, FOOD 21000원, BOOK 25000원이 나옵니다.

아래 문제는 **앞 문제의 수정을 유지한 채 순서대로** 진행합니다. 한 문제를 양쪽에 작성한 뒤 확인을 요청해도 됩니다. 다음 문제의 정답 코드는 미리 구현하지 않았습니다.

## 1. 같은 카테고리 지출 추가

두 파일의 지출 목록에 아래 한 건을 추가하세요.

| 날짜 | 카테고리 | 금액 |
| --- | --- | --- |
| 2026-10-02 | FOOD | 5000 |

수정 위치는 main의 `expenses` 목록 구성 부분입니다. 8은 기존 add 줄을 참고하고, 21은 List.of 안에 원소를 추가하거나 목록 생성 직후 add를 사용하세요. 21 예제도 ArrayList로 감싸져 있어 add가 가능합니다.

완료 조건: 전체 51000원, FOOD 26000원, BOOK 25000원. 합계 계산 코드는 기존 것을 유지해도 새 입력이 반영되어야 합니다.

## 2. 새 카테고리 추가

1번의 FOOD 지출을 남기고, 아래 지출을 추가하세요.

| 날짜 | 카테고리 | 금액 |
| --- | --- | --- |
| 2026-10-02 | TRANSPORT | 3000 |

아래 형태의 출력도 추가하세요.

```text
TRANSPORT 지출: 3000
```

완료 조건: 전체 54000원, FOOD 26000원, BOOK 25000원, TRANSPORT 3000원.

확인할 점: 8 버전의 Map에서 처음 등장한 카테고리를 어떻게 처리하는지, 21 버전의 groupingBy가 새 그룹을 어떻게 만드는지 읽어봅니다. 카테고리를 if문으로 하나씩 나열해서 추가하지 않습니다.

## 3. 한 건이 1만원 이상인 지출만 합계

전체·카테고리 합계를 유지하면서 **개별 지출 금액이 10000원 이상인 건만** 더한 결과를 새로 출력하세요. 카테고리 총액을 기준으로 고르는 문제가 아닙니다. 10000원인 지출도 포함합니다.

```text
1만원 이상 지출: 37000
```

- 8 버전: 새 합계 변수를 만들고 반복문 안에서 조건에 맞는 금액만 더합니다.
- 21 버전: Stream에서 조건으로 고른 뒤 금액을 꺼내 합산합니다.
- 힌트: BigDecimal은 `>=`로 비교할 수 없습니다. `금액.compareTo(기준금액)`의 결과를 이용합니다. 작으면 음수, 같으면 0, 크면 양수입니다.

현재 데이터에서는 12000원과 25000원만 포함됩니다. 경계값을 시험하고 싶다면 임시로 10000원 지출을 추가해 포함 여부를 확인한 뒤 원래 입력으로 되돌립니다.

## 4. 날짜별 합계 출력

카테고리별 합계와 별도로 날짜별 금액을 모아 아래처럼 출력하세요. 날짜는 오름차순입니다.

```text
날짜별 지출: {2026-10-01=37000, 2026-10-02=17000}
```

- 8 버전: 카테고리 Map 집계 방식을 참고해 키가 LocalDate인 Map을 만듭니다.
- 21 버전: groupingBy에서 그룹 기준을 카테고리 대신 날짜로 바꿔 별도의 집계를 만듭니다.
- 날짜 순서가 필요하면 TreeMap을 참고하세요. 입력 순서가 섞여도 날짜순으로 나와야 합니다.

## 5. 추가 도전: 잘못된 금액 거절

앞 문제 결과를 확인한 다음 진행하세요. 지출 객체를 만들 때 금액이 0 이하이면 IllegalArgumentException을 발생시키도록 두 버전을 바꿔봅니다.

- 8: Expense 생성자에서 확인합니다.
- 21: record의 생성자 검증 방법을 추가로 익힙니다. 이 부분은 지금 기본 문법보다 다음 단계입니다.
- 정상 입력은 기존 결과가 유지되고, 0 또는 -1000을 임시로 넣으면 오류로 실행이 종료되어야 합니다. 잘못된 금액을 조용히 건너뛰는 방식과 구분합니다.

## 확인 요청

예: `지출 1번 양쪽 수정했어. 확인해줘.`

에이전트가 현재 파일을 읽고 두 버전을 컴파일·실행해 결과를 확인합니다. 수정한 코드를 먼저 정답으로 덮어쓰지 않고, 입력 변화·문법·계산 흐름을 설명합니다.

## TreeMap과 LinkedHashMap 차이

현재 예제에서 사용하는 이름은 `LinkedHashMap`입니다. 요청한 ‘listmap’은 이 클래스를 기준으로 비교합니다. `List`는 원소 목록, `Map`은 키로 값을 찾는 자료구조이며 서로 다른 타입입니다.

| 기준 | LinkedHashMap — 기본 생성자 | TreeMap — 기본 생성자 |
| --- | --- | --- |
| 순회·출력 순서 | 키가 처음 들어온 순서 | 키의 자연 정렬 순서 |
| 날짜를 10/2 → 10/1로 넣으면 | 10/2 → 10/1 | 10/1 → 10/2 |
| 현재 쓰는 곳 | 카테고리별 합계 | 날짜별 합계 |
| 같은 키에 다시 put하면 | 값을 교체, 기존 입력 순서 유지 | 값을 교체, 키 정렬 순서 유지 |

```java
LocalDate first = LocalDate.of(2026, 10, 1);
LocalDate second = LocalDate.of(2026, 10, 2);

Map<LocalDate, Integer> inserted = new LinkedHashMap<>();
inserted.put(second, 17000);
inserted.put(first, 37000);
System.out.println(inserted); // {2026-10-02=17000, 2026-10-01=37000}

Map<LocalDate, Integer> sorted = new TreeMap<>();
sorted.put(second, 17000);
sorted.put(first, 37000);
System.out.println(sorted);   // {2026-10-01=37000, 2026-10-02=17000}
```

둘 다 합계를 자동 계산하지 않습니다. `put(날짜, 금액)`만 반복하면 같은 날짜의 기존 금액을 덮어씁니다. 반복문에서는 이전 금액을 가져와 현재 금액과 더한 값을 저장하고, Stream에서는 reducing으로 그룹별 금액을 더합니다. `TreeMap`은 그 결과를 날짜순으로 보여주는 역할입니다.

LinkedHashMap은 기본적으로 입력 순서이며 별도 생성자 옵션으로 접근 순서를 쓰는 방식도 있습니다. TreeMap은 기본 자연 순서 외에 Comparator로 정렬 기준을 지정할 수 있습니다. 이번 문제는 기본 생성자로 비교합니다.

공식 문서: [LinkedHashMap](https://docs.oracle.com/javase/8/docs/api/java/util/LinkedHashMap.html), [TreeMap](https://docs.oracle.com/javase/8/docs/api/java/util/TreeMap.html).
