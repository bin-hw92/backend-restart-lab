# 지출 문제 첫 채점

## 최종 구현 확인 — PR 준비 시점

사용자가 Java 8의 날짜 누적 위치와 TreeMap 선택을 수정했고, Java 21에도 조건합계·날짜 집계·record 검증을 적용했습니다. 두 버전의 1~5번 구현을 확인했습니다. PR 정리 과정에서 TRANSPORT 단독 출력을 추가하고, Java 8의 활성 0원 테스트를 기본 정상 실행과 분리하려고 주석 처리했습니다. 풀이 로직은 유지하고 오래된 오류 설명 주석을 현재 상태로 갱신했습니다.

양쪽의 정상 입력 결과는 전체54000, FOOD26000, BOOK25000, TRANSPORT3000, 1만원이상37000, 날짜별10/1=37000·10/2=17000으로 일치합니다. 실제 run-sample.sh 실행 확인. 임시 복사본에서 정확히10000 포함, 양수0.50 허용, 0/-1000 생성 시 예외, 날짜 입력 순서를 뒤집어도 TreeMap 날짜순 출력 확인(8/21 각각6가지 조건).

5번의 Java 8 생성자 검증은 에이전트 첨삭으로 적용했고 Java 21은 사용자가 주석 예시를 참고해 적용한 코드입니다. 구현·실행 확인과 사용자의 독립 이해 완료는 구분합니다. 아래는 이전 채점 이력입니다.

## Java 8 두 번째 채점과 첨삭

사용자가 3번을 BigDecimal total2와 >= 0 조건으로 수정하고, 4번 키를 LocalDate로 변경했습니다. 0원 테스트 입력도 주석 처리한 상태입니다. 새 5번 시도는 `compareTo`의 int를 그대로 if 조건에 쓰고, 반환값 없는 println을 throw해 두 컴파일 오류가 있었습니다.

- 1번 완료, 2번 집계 완료·TRANSPORT 단독 출력은 아직 빠짐.
- 3번 완료: 정상 5건에서 37000, 임시로 정확히 10000 추가 시 47000 확인.
- 4번은 아직 미완료: put이 날짜가 처음 등장할 때만 실행되어 12000/9000 출력. 목표는 37000/17000. LocalDate 키 변경은 반영됐지만 누적 위치와 날짜 정렬 수정이 남음.
- 5번은 에이전트가 **실행 코드에 첨삭 적용**: 생성자에서 `amount.compareTo(BigDecimal.ZERO) <= 0` 비교 후 `throw new IllegalArgumentException(...)`. 사용자의 이전 두 시도는 주석으로 보존. 양수 0.50은 정상 생성, 0/-1000은 생성 시 예외·비정상 종료 확인. 이것은 사용자 독립 풀이 완료와는 구분함.

4번의 현재 코드는 보존하고 해당 위치에 남은 수정 안내를 갱신했습니다. Java 21은 이번 요청에서 변경하지 않았습니다. 아래 내용은 첫 채점 당시 기록입니다.

---

사용자가 작성한 8/21 파일을 각각 컴파일·실행해 확인했습니다. 코드 기능은 그대로 두고, 오류 위치의 주석과 참고 수정안을 추가했습니다. 참고 코드는 주석이라 현재 실행에는 적용되지 않습니다.

## 문제별 결과

| 문제 | Java 8 | Java 21 | 확인한 내용 |
| --- | --- | --- | --- |
| 1 FOOD 5000 추가 | 완료 | 완료 | 입력 추가와 기존 집계 정상 |
| 2 TRANSPORT 3000 | 부분 완료 | 부분 완료 | 카테고리 Map에 3000 반영. TRANSPORT 단독 출력만 누락 |
| 3 개별 1만원 이상 합계 | 수정 필요 | 수정 필요 | 8은 중복 합산·Map 반환·10000 제외. 21은 조건 없이 FOOD 합계 출력 |
| 4 날짜별 합계 | 수정 필요 | 구현 필요 | 8은 날짜의 첫 금액만 기록. 21은 날짜 집계 없이 FOOD 합계 출력 |
| 5 0 이하 생성 거절 | 수정 필요 | 구현 필요 | 8은 문자열 출력+break로 정상 종료. 21은 생성자 검증 없음 |

0원 테스트 항목을 제외한 정상 5건의 목표: 전체54000, FOOD26000, BOOK25000, TRANSPORT3000, 1만원이상37000, 날짜별10/1=37000·10/2=17000.

## Java 8에서 실제로 나온 결과

```text
IllegalArgumentException
전체 지출: 54000
카테고리별 지출: {FOOD=26000, BOOK=25000, TRANSPORT=3000}
FOOD 지출: 26000
1만원 이상 지출: {FOOD=24000, BOOK=50000}
날짜별 합계 지출: {2026-10-01=12000, 2026-10-02=9000}
```

`IllegalArgumentException`이라는 첫 줄은 예외의 발생 기록이 아니라 사용자가 직접 println한 문자열입니다. 실제 종료 코드는 0이었습니다.

3번: 먼저 byCategory에 금액을 더한 다음 그 값을 previous2로 가져와 금액을 한 번 더 더합니다. FOOD 첫 건이 12000+12000=24000, BOOK이 25000+25000=50000이 되는 이유입니다. 이 문제는 카테고리별 Map이 아닌 BigDecimal 한 개의 합계이므로 별도 highValueTotal을 준비하면 됩니다.

4번: `if (날짜의 값 == null)` 안에서만 put해 같은 날짜의 두 번째 금액부터 누적되지 않습니다. null일 때만 초기값을 정하고, 누적 put은 매번 해야 합니다. TreeMap의 LocalDate 키로 날짜순을 보장할 수 있습니다.

5번: break는 반복문만 끝내며 아래 출력은 계속합니다. 객체 생성 시점에 throw가 필요합니다. intValue 대신 compareTo를 쓰면 소수와 큰 금액의 값을 훼손하지 않고 비교할 수 있습니다.

## Java 21에서 실제로 나온 결과

```text
전체 지출: 54000
카테고리별 지출: {FOOD=26000, BOOK=25000, TRANSPORT=3000}
FOOD 지출: 26000
1만원 이상 지출: 26000
날짜별 지출: 26000
```

byCategory2는 조건 없이 기존 카테고리 계산을 복사한 것이며 출력에서도 사용되지 않습니다. 3번은 filter → map → reduce로 숫자 하나를 구하고, 4번은 날짜를 기준으로 groupingBy합니다. 5번은 record compact constructor에서 검증합니다. 해당 위치에 복사해서 비교할 수 있는 주석 풀이를 추가했습니다.

## 추가 확인

실습 파일을 덮어쓰지 않고 임시 복사본으로 확인했습니다.

- 8에서 0원 항목 제거: 3·4번 오류가 그대로 나타남. 0원 때문만은 아님.
- 8에 정확히 10000원 추가: 1만원 이상 집계에 포함되지 않음. 조건을 > 0에서 >= 0으로 바꿔야 함.
- 8의 첫 금액을 0.50으로 변경: 양수인데 intValue가 0이 되어 오류 문자열 출력·반복 중단. compareTo 필요.

주석의 수정안도 별도 임시 프로그램으로 Java 8/21 각각 검증했습니다. 정상 5건의 목표 합계 일치, 정확히 10000원 포함, 양수 0.50 허용, 0/-1000은 생성 시 IllegalArgumentException으로 비정상 종료함을 확인했습니다. 이 결과는 참고 수정안의 검증이며 사용자의 현재 풀이가 수정 완료됐다는 뜻은 아닙니다.

## 수정 순서

1. 0원 테스트 줄을 잠시 제외하고 8의 3번부터 수정합니다.
2. 21의 같은 3번 주석 풀이를 보며 적용해 결과를 비교합니다.
3. 날짜별 4번과 TRANSPORT 출력까지 수정합니다.
4. 마지막으로 생성자 검증을 추가하고 정상/0/음수 입력을 따로 실행합니다. 0원 테스트를 남겨두면 생성자에서 종료되어 집계는 실행되지 않는 것이 맞습니다.
