# Java 8과 Java 21로 같은 예제 고쳐보기

2026-10-14. 사용자는 아이맥스소프트 때 익숙한 방식과 최신 방식을 나란히 수정하고, 에이전트가 실행 결과와 수정 내용을 설명하는 방식으로 공부하려고 합니다.

## 어떤 파일을 고칠지

| 예제 | Java 8 방식 | Java 21 방식 |
| --- | --- | --- |
| 성적 집계 — 먼저 연습 | [java8/GradeSummary.java](java8/GradeSummary.java) | [java21/GradeSummary.java](java21/GradeSummary.java) |
| 지출 집계 — 기존 예제 비교 | [ExpenseSummaryJava8.java](ExpenseSummaryJava8.java) | [ExpenseSummaryJava21.java](ExpenseSummaryJava21.java) |

기존 `ExpenseSummary.java`는 원래 예제와 사용자 수정 기록을 보존한 파일입니다. 앞으로 지출 비교는 버전 이름이 붙은 두 파일에서 합니다.

성적 예제는 일반 클래스·생성자·getter·인덱스 for문·if를 쓰는 8 버전과 record·Stream을 쓰는 21 버전으로 구성했습니다. 입력과 출력 순서를 같게 맞췄습니다. 지출 예제도 같은 순서로 출력하고, 두 버전 모두 목록에 add()로 새 항목을 넣을 수 있습니다.

## 실행

```sh
cd ~/Desktop/project/backend-restart-lab/java-basics

# 성적 예제
bash run-sample.sh 8 grade
bash run-sample.sh 21 grade

# 지출 예제
bash run-sample.sh 8 expense
bash run-sample.sh 21 expense
```

두 버전 모두 설치된 **JDK 21**로 실행합니다. 8 버전은 `javac --release 8`, 21 버전은 `--release 21`로 컴파일해 문법과 표준 API 범위를 구분합니다. Java 8 런타임에서 실제 실행한 것과는 구분하며 별도 JDK 8 설치는 필요하지 않습니다. 컴파일할 때마다 새 임시 폴더를 사용하므로 컴파일 실패 뒤 오래된 class를 실행하지 않습니다.

8 버전 실행 시 오래된 컴파일 대상에 대한 경고가 나올 수 있습니다. 문법 오류와는 다릅니다.

성적 예제의 최초 실행 결과:

```text
학습자 수: 3
점수 합계: 210
통과: 2
미통과: 1
통과 학습자: [학습자A, 학습자C]
```

지출 예제의 최초 실행 결과:

```text
전체 지출: 46000
카테고리별 지출: {FOOD=21000, BOOK=25000}
FOOD 지출: 21000
```

## 첫 수정

성적 두 파일에서 `학습자B` 점수를 **55에서 65**로 바꿔보세요. 실행 전에 점수 합계와 통과 인원이 어떻게 바뀔지 생각해 봅니다. 수정 후 `성적 두 버전 수정했어. 확인해줘`라고 알려주면 됩니다. 결과를 붙여 넣지 않아도 로컬 파일을 확인하고 실행할 수 있습니다.

다음에는 하나씩 진행합니다.

1. 학습자D의 점수 60을 목록에 추가. `>=`와 `>`의 차이 확인.
2. 통과 기준 PASS_SCORE를 70으로 변경. 기준값과 처리 로직 구분.
3. 미통과 학습자 이름도 출력하도록 두 버전 수정.
4. 0~100 밖의 점수를 어떻게 처리할지 정한 뒤 입력 검증 추가.
5. 지출 예제에서 한 건 추가하고 카테고리별 결과 비교.

풀이를 먼저 완성하기보다 사용자가 바꾼 코드와 결과를 보고 다음 문제를 정합니다.

## 결과를 확인하는 방식

에이전트는 사용자가 수정한 파일을 보존하고 다음 순서로 확인합니다.

1. 어떤 입력·조건·코드를 바꿨는지 읽습니다.
2. 양쪽을 각각 컴파일하고 실제 출력을 비교합니다.
3. 예상과 일치하는지, 결과가 다르다면 어느 입력/조건/처리에서 달라졌는지 설명합니다.
4. Java 8 코드의 한 줄이 최신 코드의 어느 부분과 연결되는지 설명합니다.
5. 문법 오류나 로직 문제는 원인과 최소 수정안을 먼저 설명하고 사용자의 연습 코드를 곧바로 정답으로 덮어쓰지 않습니다. 실행 성공을 이해 완료로 기록하지 않습니다.

## 알아둘 차이

각 성적 Java 파일에 코드별 설명 주석을 추가했습니다. 함수·문법의 도입 버전과 반복문 대응은 [JAVA_TERMS.md](JAVA_TERMS.md)에 있습니다. List.forEach와 Stream.forEach, 람다, 메서드 참조, filter/map/mapToInt/sum/toList, record를 현재 실습 코드로 설명합니다.

| 항목 | 익숙한 방식 | 최신 방식과 주의점 |
| --- | --- | --- |
| 데이터 한 건 | 클래스·필드·생성자·getter | record는 생성자·접근자·equals/hashCode/toString 등을 제공. 필드 변경이 필요하면 일반 클래스 유지도 가능 |
| 값 읽기 | `grade.getScore()` | `grade.score()` |
| 합계 | for문에서 누적 | `mapToInt(...).sum()` |
| 조건에 맞는 항목 | if 분기 | `filter(...)` |
| 이름 목록 | ArrayList에 add | `map(...).toList()`; 결과 목록은 수정 불가 |

record는 Java 16부터 정식 제공, List.of는 Java 9부터, Stream.toList는 Java 16부터입니다. **Stream·람다·메서드 참조 자체는 Java 8에도 있습니다.** 따라서 새로 보이는 모든 문법이 Java 21에서 처음 생긴 것은 아닙니다. `List.of()`도 수정 불가여서, 지출 21 예제에서는 `new ArrayList<>(List.of(...))`로 수정 가능한 목록을 만들었습니다.
