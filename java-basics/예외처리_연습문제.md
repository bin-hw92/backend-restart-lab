# 다음 실습: 잘못된 지출을 처리하고 계속하기

현재 지출 예제는 금액이 0 이하이면 생성자가 예외를 던집니다. 예외를 처리하는 catch가 없어 프로그램 전체가 종료됩니다. 다음에는 **잘못된 지출만 등록에 실패하고 정상 지출의 합계는 계속 출력**하도록 바꿔봅니다.

수정 파일: [ExpenseSummaryJava8.java](ExpenseSummaryJava8.java), [ExpenseSummaryJava21.java](ExpenseSummaryJava21.java). 생성자의 검증은 유지합니다. Java 8과 21 모두 try-catch 문법을 사용할 수 있습니다.

## 1. 0원 등록 실패를 처리하기 — 우선 이 문제만

정상 지출 5건을 유지하고, 0원 지출을 한 건 등록하려고 시도합니다. IllegalArgumentException을 catch해 아래 메시지를 출력하세요.

```text
등록 실패: 금액은 0보다 커야 합니다.
```

그 이후 합계도 계속 출력되어야 합니다.

```text
전체 지출: 54000
카테고리별 지출: {FOOD=26000, BOOK=25000, TRANSPORT=3000}
FOOD 지출: 26000
TRANSPORT 지출: 3000
1만원 이상 지출: 37000
날짜별 지출: {2026-10-01=37000, 2026-10-02=17000}
```

### 수정 위치

- 8: 주석 처리된 0원 `expenses.add(new Expense(...))` 줄을 try 안에서 실행합니다. 기존 정상 지출 등록은 유지합니다.
- 21: 정상 목록 생성이 끝난 `));` **다음**에 0원 지출을 add하는 시도를 넣습니다. List.of 안의 0원 주석은 그대로 둡니다. 그 안에서 예외가 발생하면 전체 목록 생성이 끝나지 않기 때문입니다.
- catch 대상은 IllegalArgumentException. 메시지는 예외 객체의 getMessage()로 읽습니다.
- 합계 계산 반복문/Stream을 try 안으로 옮기지 않습니다. 오류는 합계 계산 전 객체를 만드는 순간 발생합니다.

### 직접 채울 구조

```java
try {
    // 이 안에서 0원 지출을 만들어 expenses에 추가하려고 시도
} catch (IllegalArgumentException e) {
    // "등록 실패: " 뒤에 e.getMessage()를 붙여 출력
}

// 아래의 기존 합계 계산과 출력은 계속 실행
```

생성자가 예외를 던지면 new Expense(...)가 완료되지 않아 add도 실행되지 않습니다. catch는 오류를 처리하고, 그 뒤의 코드로 이어갑니다. 검증 조건을 지우거나 0원 데이터를 정상 등록하는 방식으로 통과시키지 마세요.

## 2. 음수도 독립적으로 처리하기

1번 확인 후 -1000원 지출의 등록 시도도 추가하세요. 0원과 음수 각각 실패 메시지가 나와 총 2개이고, 정상 합계는 54000원이어야 합니다. 두 등록을 한 try에 넣었을 때 첫 오류 뒤 두 번째 줄이 실행되는지 먼저 생각해 보세요. 각 등록을 독립적으로 시도할 수 있게 만듭니다.

## 3. 등록을 메서드로 나누기

반복되는 등록/오류 처리를 별도의 메서드로 옮겨 main은 어떤 지출을 등록할지만 적도록 정리해봅니다. 목록·날짜·카테고리·금액을 어떻게 전달할지 생각해 봅니다. 이 단계는 1·2번을 확인한 뒤 진행합니다.
