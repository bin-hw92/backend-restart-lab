# 예외처리 답지: 왜 여기서 throw하고 여기서 catch할까?

2026-10-15. 사용자가 답지를 먼저 공부하고 싶다고 요청해 에이전트가 작성한 참고 풀이입니다. 답지 작성 당시 기존 `ExpenseSummaryJava8.java`, `ExpenseSummaryJava21.java`는 수정하지 않았습니다. 2026-10-16 GitHub 업로드 정리에서 원본 8의 잘못된 시도는 주석으로 보존하고 기존 생성자 throw 검증을 복구했습니다. 새 문제는 현재 작업의 PR 머지와 브랜치 정리 후 별도 파일로 준비할 예정입니다.

먼저 [Java 8 답지](ExpenseExceptionAnswerJava8.java)의 **[A] 생성자 → [B-1] 0원 등록 → [C] 합계** 순서로 읽으세요. 그다음 [B-2] 음수 등록과 [D] 메서드 분리를 봅니다. [Java 21 답지](ExpenseExceptionAnswerJava21.java)에서도 예외처리 부분은 같습니다. record와 집계 방식만 비교하면 됩니다.

## 가장 중요한 세 역할

| 코드 | 하는 일 | 이 예제에서의 위치와 이유 |
| --- | --- | --- |
| `throw new IllegalArgumentException("설명")` | 설명을 담은 예외를 만들어 던지고 현재 정상 실행을 중단 | 생성자: 0원 이하인 지출이 만들어지는 것을 거절 |
| `try { 등록 시도; }` | 실행 중 생긴 예외를 뒤의 catch에서 처리할 수 있게 범위를 지정 | main: 실패할 수 있는 생성·추가를 시도 |
| `catch (IllegalArgumentException e) { ... }` | 해당 타입의 예외를 받아 처리 | main: 이번 등록 실패를 알리고 다음 작업을 계속 |

`IllegalArgumentException`은 메서드나 생성자에 전달한 인자가 적절하지 않다는 뜻으로 쓰는 표준 예외 클래스입니다. 이 예제에서는 금액이 조건에 맞지 않을 때 사용합니다. `e`는 변수를 붙인 이름이라 `exception`으로 바꿔도 됩니다.

생성자는 **어떤 금액이 올바른지** 판단하고, 등록하는 쪽은 **실패했을 때 어떻게 알리고 계속할지** 결정합니다. 생성자 안에서 예외를 잡고 그냥 아래로 진행하면, 거절하려던 금액을 필드에 저장할 수 있습니다. 그래서 검증의 throw는 유지하고, 호출하는 쪽에서 catch합니다.

## 0원을 넣었을 때 실제 순서

```java
try {
    expenses.add(new Expense(date, "FOOD", new BigDecimal("0")));
} catch (IllegalArgumentException e) {
    System.out.println("등록 실패: " + e.getMessage());
}
// 다음 합계 계산으로 진행
```

1. `add(...)`에 전달할 값을 구하기 위해 `new Expense(...)`를 먼저 실행합니다.
2. 생성자에서 `0.compareTo(0) <= 0`이 참이므로 `throw`합니다.
3. 생성자가 중단되어 정상 객체 생성이 완료되지 않습니다. `add`도 호출되지 않아 목록에 0원 데이터가 들어가지 않습니다.
4. 호출한 쪽의 `catch (IllegalArgumentException e)`로 이동합니다. 예외가 생긴 뒤 남은 try 내부 코드는 건너뜁니다.
5. `e.getMessage()`로 예외에 담긴 문장을 읽고 `println`으로 화면에 출력합니다.
6. 이 catch는 정상 종료하므로 try-catch 다음의 합계 계산을 실행합니다. 실패한 줄을 다시 시도하지는 않습니다.

반대로 **정상 금액이면** 생성과 add를 마치고 catch를 건너뜁니다. try-catch가 있다고 매번 catch가 실행되는 것은 아닙니다. 여기서는 IllegalArgumentException을 처리하며, 다른 종류의 예외까지 모두 처리하는 것은 아닙니다.

## 지금 작성한 코드에서 헷갈렸던 부분

사용자가 Java 8 연습 파일에 작성했던 빈 try와 `e.getMessage("금액은 0보다 커야 합니다.")`는 다음처럼 구분해서 보면 됩니다. 해당 시도는 원본 파일 안의 주석에 보존했습니다.

```java
// 1. 예외 객체를 만들 때 설명을 넣습니다.
throw new IllegalArgumentException("금액은 0보다 커야 합니다.");

// 2. catch에서 그 설명을 읽을 때는 인자를 넣지 않습니다.
// 이 두 줄은 위 throw 바로 다음이 아니라, catch 안에 들어갈 코드입니다.
String message = e.getMessage();
System.out.println("등록 실패: " + message);
```

- `getMessage("...")`는 제공되는 호출 형태가 아니어서 컴파일되지 않습니다. `getMessage()`가 맞습니다.
- `getMessage()`는 메시지를 **설정하거나 출력하지 않고 문자열로 반환**합니다. 화면 출력은 `System.out.println(...)`이 합니다.
- 비어 있는 try는 이번 금액 검증 예외를 발생시키지 않습니다. try가 스스로 금액을 검사하는 것도 아닙니다.
- `new IllegalArgumentException(...)`만 적으면 객체만 만들 뿐입니다. `throw`가 있어야 실제로 예외를 던집니다.
- try-catch는 if의 대체 문법이 아닙니다. if는 금액 조건을 판단하고, try-catch는 실행 중 던져진 예외를 처리합니다.

## 음수는 왜 별도 try에 넣을까? — 문제 2

```java
try {
    // 0원 등록: 여기서 throw하면
    // -1000원 등록: 이 줄에는 도달하지 않습니다.
} catch (IllegalArgumentException e) {
    // 첫 번째 실패만 처리합니다.
}
```

각 등록을 독립적으로 시도하려고 답지에는 try-catch를 두 번 적었습니다. 따라서 실패 메시지도 두 번 나오고, 둘 다 목록에 추가되지 않습니다. 정상 5건의 합계는 그대로 54000원입니다.

## 반복을 메서드로 옮긴 형태 — 문제 3

두 Java 답지의 맨 아래 `registerExpense(...)`가 메서드로 나눈 답지입니다. 기본 실행은 흐름을 먼저 보기 위해 main의 직접 try-catch를 사용합니다.

분리한 형태를 확인하려면 main의 **[B-1]·[B-2] try-catch 전체를 아래 두 줄로 교체**합니다. 원래 블록을 남긴 채 추가하면 실패 메시지가 네 번 나오므로, 둘 중 한 형태만 사용합니다. 지금 당장 수정할 필요는 없습니다.

```java
registerExpense(expenses, LocalDate.of(2026, 10, 2), "TRANSPORT", new BigDecimal("0"));
registerExpense(expenses, LocalDate.of(2026, 10, 2), "FOOD", new BigDecimal("-1000"));
```

호출 한 번마다 메서드 안에서 생성·추가·실패 처리를 합니다. 첫 호출의 실패를 메서드 내부에서 처리하고 돌아오므로 두 번째 호출도 실행됩니다. main은 어떤 지출을 등록할지만 적고, 반복되는 try-catch는 한 곳에 모입니다. 정상 5건 등록도 같은 메서드 호출로 바꿀 수 있습니다.

| 매개변수·키워드 | 여기서의 의미 |
| --- | --- |
| `List<Expense> expenses` | 추가할 대상 목록. 전달된 참조를 복사해 받으며, main과 같은 목록 객체를 가리키므로 add 결과가 반영됨 |
| `LocalDate date`, `String category`, `BigDecimal amount` | 이번에 등록할 지출의 날짜·분류·금액 |
| `static` | 이 예제에서 static main이 답지 클래스의 인스턴스를 만들지 않고 직접 호출할 수 있게 함 |
| `void` | 호출한 쪽에 결과값을 반환하지 않음. 성공 시 목록 추가, 실패 시 메시지 출력까지 수행 |

이 예제는 콘솔 프로그램이라 실패를 출력하고 계속합니다. 모든 오류를 무조건 잡고 계속하라는 규칙은 아닙니다. 여기서는 0원·음수 등록 실패를 처리하고 정상 지출의 집계를 이어가는 것이 문제의 목표입니다.

## Java 8과 21의 차이

| 부분 | Java 8 답지 | Java 21 답지 |
| --- | --- | --- |
| 데이터 표현 | 일반 클래스·생성자·getter | record·compact constructor·접근자 |
| 검증 | 생성자에서 if + throw | record 생성자에서 같은 if + throw |
| 실패 처리 | 등록하는 쪽의 try-catch | 같은 try-catch |
| 집계 | for문·if·누적 | Stream의 map·filter·reduce·groupingBy |

**try-catch는 두 버전에서 동일하게 사용합니다.** Stream도 Java 8부터 있습니다. record는 Java 16부터 정식 제공, List.of는 Java 9부터입니다. 이번에는 예외처리 흐름부터 이해하고 집계 문법은 기존 복습 부분으로 보세요.
